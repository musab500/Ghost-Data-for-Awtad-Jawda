## 6. Team-authored evaluation cases

Four cases under `code/evaluation/custom_cases/`, each isolating logic the 32
samples cannot cleanly exercise. All currently **PASS (4/4)**.

1. **`temporal_cutoff`** — A profile FOUND in a snapshot before `audit_at` and
   deleted (NOT_FOUND) in a snapshot after it. At the cutoff the answer must be
   FOUND → REPORT_REMAINING_RECORD, citing the pre-cutoff evidence; audited
   later it must read NOT_FOUND → VERIFY_RECORD_ABSENT. Guards against using
   future evidence.
2. **`non_deletion_classifier`** — 6 non-deletion requests (opt-out, data copy,
   correction, access, login help, keep-account) must classify NOT_APPLICABLE;
   3 genuine erasure requests (including one that says "remove any remaining
   copy") must classify as deletions.
3. **`retention_and_recreation`** — A SECURITY_AUDIT_LOG inside its retention
   window must be kept (VERIFY_RECORD_PRESENT, no finding); the same record past
   retention must flip to DELETE (a finding); an ACTIVE data flow must become
   REPORT_ACTIVE_DATA_FLOW → DISABLE_DATA_FLOW → VERIFY_DATA_FLOW_DISABLED.

4. **`validator_complete_rule`** (regression) — a `COMPLETE` row with no steps
   must make strict validation raise ("no VERIFICATION step") and must be
   reported as exactly one warning in non-strict mode.

## 7. Failures found and improvements made

- **Empty `COMPLETE` rows (case_45, case_61, case_63).** The pipeline emitted
  `COMPLETE` with `[]` where evidence exists only in images/PDFs not yet loaded
  (`multimodal.py`, Person A). The validator now rejects a `COMPLETE` row without
  a `VERIFICATION` step or with an uncited step. It is strict once multimodal
  observations are loaded and prints these cases as warnings until then.

- **Classifier false positive on case_05.** The phrase list matched "copy of
  my profile" inside a deletion request. Fix: replaced the broad `"copy of my"`
  signal with specific access phrases (`copy of my invoices/data/records`). Now
  0 sample false positives and exactly the 10 flagged full-set cases. Added as
  a regression check inside the `non_deletion_classifier` custom case.
- **Baseline-regression guard.** `evaluation/main.py` asserts status ≥ 31/32,
  exact-seq ≥ 24/32, precision ≥ 0.973, recall ≥ 0.943, and fails loudly if a
  change regresses the deterministic core.
- **Loud output validation.** `main.validate_output_file` independently
  re-checks every output row (row count, sort order, JSON validity, consecutive
  `step_no`, phase/operation/state legality, within-phase ordering, and the full
  evidence-citation contract) and raises on any violation.

## 9. Honest limitations on the hidden set

- The 32 public samples are a small set; they confirm the status logic and the
  step contract but cannot measure accuracy on the 518 hidden cases. Workflow
  assignment costs were checked for generality, not tuned to labels.
- `multimodal.py` is not yet integrated, so any hidden case whose only evidence
  is in a PDF or PNG (15 such files exist) is currently under-served, exactly as
  `case_07` shows. This is the highest-value remaining integration.
- Near-simultaneous, identifier-less records (the case_03/27/28 family) remain
  ambiguous by construction; status is still correct, only the cited resource id
  can differ.
